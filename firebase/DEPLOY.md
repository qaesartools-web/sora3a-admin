# دليل تفعيل نظام الحماية والإشعارات — منظومة سرعة

> التطبيقات الجديدة متوافقة مع الحسابات الحالية، فلا أحد ينقطع عن الدخول بعد الدمج.
> نفّذ الخطوة 2 ثم 3 بنفس اليوم حتى تتفعّل الحماية الكاملة.

## الخطوة 1 — دمج التحديثات (GitHub)

ادمج فرع `claude/stoic-einstein-xmxbri` في `main` في المستودعات الثلاثة:

1. `sora3a-admin` (لوحة الإدارة + ملفات الحماية)
2. `sora3a-rest2` (المطعم / الكاشير)
3. `sora3a-captain` (الكابتن + صفحة التتبع)

انتظر دقيقتين حتى تتحدث صفحات GitHub Pages.

## الخطوة 2 — ربط الحسابات القديمة (من لوحة الإدارة)

1. افتح لوحة الإدارة وادخل بحساب المدير.
2. اذهب لتبويب **🛡️ الأمان**.
3. اضغط **🔍 فحص** ← ثم **✅ تطبيق الإصلاحات**.
4. راجع قائمة **حسابات الإدارة العليا**: أي حساب لا تعرفه اضغط **⛔ إيقاف**.
5. إذا ظهرت ملاحظات "تحتاج مراجعة" (مثلاً مطعم بدون حساب دخول) عالجها أولاً.

## الخطوة 3 — نشر قواعد الحماية (من المتصفح، بدون برامج)

1. افتح https://console.firebase.google.com واختر مشروع **sora3a-system**.
2. من القائمة: **Firestore Database** ← تبويب **Rules**.
3. احذف كل النص الموجود، والصق محتوى الملف `firebase/firestore.rules` بالكامل.
4. اضغط **Publish**.

✅ من هذه اللحظة: لا أحد يستطيع منح نفسه صلاحيات، ولا مطعم يرى بيانات مطعم آخر،
ولا زائر يرى هواتف أو عناوين الزبائن.

> إذا واجه أي حساب مشكلة دخول بعد النشر: ارجع لتبويب الأمان واضغط "فحص" — سيخبرك بالسبب.

## الخطوة 4 — الإشعارات والتطبيق مغلق (يحتاج خطة Blaze)

الإشعارات **داخل التطبيق** وعندما يكون **بالخلفية** تعمل الآن بدون أي شيء إضافي.
لكي تصل الإشعارات للكابتن **حتى والتطبيق مغلق تماماً** يلزم "سيرفر" صغير من Firebase:

1. في Firebase Console: الإعدادات ⚙️ ← **Usage and billing** ← **Modify plan** ← اختر **Blaze** واربط بطاقة.
   (بحجم الاستخدام الحالي غالباً لا توجد تكلفة، ويمكنك وضع حد أقصى للميزانية.)
2. على أي كمبيوتر فيه Node.js، نفّذ الأوامر التالية مرة واحدة:

```bash
npm install -g firebase-tools
firebase login
git clone https://github.com/qaesartools-web/sora3a-admin
cd sora3a-admin/firebase/functions && npm install && cd ..
firebase deploy --only functions
```

بعدها: كل طلب جديد يصل للكابتن كإشعار مع صوت واهتزاز، والمطعم يصله إشعار عند رفض الكابتن أو عند التسليم.

## ماذا يحتاج الكابتن أن يفعل؟

- يفتح التطبيق ويسجل الدخول ← تظهر له نافذة **"فعّل الإشعارات"** ← يضغط **تفعيل** ← **سماح**.
- **آيفون:** يجب أولاً إضافة التطبيق للشاشة الرئيسية (مشاركة ← إضافة إلى الشاشة الرئيسية) وفتحه من هناك.
- **أندرويد:** يُفضّل تثبيت التطبيق من زر "📲 تثبيت التطبيق".

## اختبار القواعد (للمطورين)

```bash
cd firebase && npm install && npm test
```

## الكاشيرية والصلاحيات + خطوط الاتصال (توكن جوكر)

> بعد أي تحديث لملف `firestore.rules` أعد لصقه في Firebase ← Firestore ← Rules ← Publish.

1. **الكاشيرية (المدير الأعلى فقط):** لوحة الإدارة بحساب المدير الأعلى ← تبويب **☎️ الكاشيرية والخطوط** ← اختر المطعم ← أضف كاشير
   (اسم + إيميل + كلمة مرور لكل كاشير)، ومنها توقفه ⏸️ أو تفعّله أو تحذفه. صاحب المطعم ما يكدر يضيف أو يوقف أو يحذف كاشير
   (القواعد على السيرفر تمنعه) — بس يحدد الصلاحيات (الخصم، الإلغاء، المخزون، المنيو، الإعدادات) والدوام. أي تغيير يطبّق فوراً على جهاز الكاشير.
2. **خطوط الاتصال:**
   - **الأسهل (بدون MacroDroid):** على تلفون الخط ثبّت تطبيق **«سرعة — خط المطعم»** (`releases/download/line-android/sora3a-line.apk`) ← دخول بحساب صاحب المطعم ← اكتب الرقم ← «اربط» واسمح بالأذونات (الهاتف وسجل المكالمات، الوصول للإشعارات للواتساب، إيقاف توفير البطارية). الخط ينضاف للمطعم وحده (حتى ١٠ خطوط)، ونفس الرقم على تلفون جديد يستخدم نفس الخط.
     - تطبيق خط المطعم يقرأ الإشعارات (للواتساب)، فـ Google Play Protect يحظر تثبيته من برّا المتجر: أطفِ «فحص التطبيقات» مؤقتاً، ثبّت، ورجّعه. تطبيق الكاشير ما يطلب هالأذونات فيتثبت عادي.
   - أو يدوياً (سنترال / هاتف IP / MacroDroid): بنفس التبويب ← **⚙️ متقدم** ← **إضافة خط يدوي** ← **طريقة الربط** تعرض التوكن وخطوات MacroDroid جاهزة للنسخ.
   - على كل جهاز أندرويد: MacroDroid ← Trigger: *Call Incoming* ← Action: *HTTP Request (POST)* بالرابط والـ Body المعروضين.
   - اختياري: Constraint *WiFi SSID* = واي فاي المطعم، حتى لا يرسل إلا داخل المطعم.
   - زر **🧪 مكالمة تجريبية** يتأكد أن الكاشير يستلم المكالمات.
   - إذا تسرّب توكن: **🔄 توكن جديد** يوقف القديم فوراً.
3. **دوام الكاشير:** بنفس التبويب، لكل كاشير ⏰ **الدوام من … إلى …** ← **💾 حفظ الدوام** (يدعم الدوام الليلي مثل ٨ مساءً ← ٢ فجراً).
   - قبل النهاية بـ ١٠ و ٥ دقائق يظهر تنبيه للكاشير.
   - عند النهاية: تُغلق الوردية التي فتحها تلقائياً وتنطبع **فاتورة المبلغ الكلي (تقرير Z)**، ثم يُقفل الكاشير.
   - خارج الدوام لا يستطيع الكاشير العمل حتى لو تلاعب بساعة الجهاز (القواعد على السيرفر تمنعه، مع ١٥ دقيقة سماح بعد النهاية لإغلاق الوردية).
   - يفتح تلقائياً عند بداية دوامه. **بدون وقت** = بلا قيود.

## خدمات المطعم (المدير الأعلى فقط)

لوحة الإدارة ← **🍽️ المطاعم** ← تحت كل مطعم سطر **الخدمات**. اضغط أي خدمة لتشغيلها ✅ أو إيقافها ⛔:

- **🛵 الكابتن والدلفري:** عند الإيقاف يختفي الدلفري من الكاشير، ويختفي تبويبا الكباتن والخريطة من لوحة المطعم، والكابتن لا يستطيع الدخول.
- **📞 اتصال الشريحة** و **💬 مكالمات واتساب:** عند الإيقاف يرفض السيرفر مكالمات ذلك النوع. الخط الذي اسمه يحتوي "واتساب" يُعتبر واتساب.
- **📟 البيجر:** يختفي شريط البيجر من الكاشير.

صاحب المطعم لا يستطيع تغيير خدماته، والقواعد على السيرفر تفرض ذلك. **يتطلب نشر ملف القواعد الجديد.**

## الأجهزة المعتمدة (المدير الأعلى فقط)

حتى الكاشير ما يفتح حسابه من بيته أو من مطعم ثاني: كل حساب كاشير يشتغل بس على الأجهزة اللي يعتمدها المدير الأعلى للمطعم، وعلى جهاز واحد بنفس الوقت.

1. الكاشير يدخل بإيميله على جهاز جديد ← يطلع له **«هذا الجهاز مو معتمد لمطعمك»** ورمز من ٦ حروف (مثل `K7M2QX`).
2. يتصل بالمدير الأعلى ويقرا الرمز.
3. المدير الأعلى: لوحة الإدارة ← **🏠 الرئيسية** (بطاقة «أجهزة تنتظر اعتمادك») أو **☎️ الكاشيرية والخطوط** ← اختر المطعم ← بطاقة **🔐 أجهزة الكاشير المعتمدة**
   ← اكتب الرمز بمربع البحث ← اكتب اسم للجهاز (مثل «كاشير ١») ← **✅ اعتماد**. الجهاز يفتح عند الكاشير وحده خلال ثواني.
4. الكاشير الثاني (الوردية الثانية) على نفس الجهاز يدخل بإيميله عادي — الجهاز معتمد للمطعم، مو للشخص.
5. **🗑️ إلغاء الاعتماد** يقفل الجهاز فوراً. وإذا نفس الحساب انفتح على جهاز ثاني، الجهاز الأول ينقفل («حسابك انفتح بجهاز ثاني»).

- الخدمة **مطفية** للمطاعم القديمة و**شغّالة** تلقائياً للمطاعم الجديدة. تشغّلها/تطفيها من نفس البطاقة أو من سطر **الخدمات** تحت المطعم.
- وهي مطفية: كل جهاز يدخل منه كاشير يتسجل بالبطاقة تحت «أجهزة دخلوا منها» — اعتمدها (أو **✅ اعتماد الكل**) وبعدين شغّل الخدمة حتى ما ينقفل أحد.
- إذا الكاشير مسح بيانات التطبيق أو المتصفح، الجهاز يطلع له رمز جديد ويحتاج اعتماد من جديد.
- شاشة «طلبك جاهز» تدخل بحساب صاحب المطعم. تطبيق الويتر بحساب الكاشير يحتاج اعتماد التلفون مثل أي جهاز كاشير.
- **يتطلب نشر ملف القواعد الجديد.**

## فهرس الطلبات (مرة وحدة — مهم مع كثرة المطاعم)

الكاشير ولوحة صاحب المطعم صاروا ينزّلون بس طلبات اليوم وأمس والمفتوحة، والفترات القديمة تنجاب وقت الطلب. هذا يحتاج فهرس واحد بـ Firebase:

Firebase ← Firestore ← **Indexes** ← **Composite** ← **Create index**:
- Collection ID: `orders`
- الحقل الأول: `restaurantId` — Ascending
- الحقل الثاني: `createdAtMs` — Ascending
- Query scope: **Collection** ← **Create** (يخلص خلال دقائق)

إذا الفهرس مو موجود، لوحة الإدارة العليا تطلّع بالرئيسية تنبيه «⚠️ فهرس الطلبات مو مسوّى» بزر «إنشاء الفهرس بضغطة». وبدونه ما يوقف شي: الكاشير يرجع ينزّل كل الطلبات مثل قبل لحد ما تسويه.

## النسخ الاحتياطية (ببلاش)

1. **تنزيل يدوي:** لوحة الإدارة العليا ← **🛡️ الأمان** ← «📥 تنزيل نسخة من الطلبات» ← اختر المطعم والفترة ← Excel أو نسخة كاملة (JSON).
2. **نسخة ليلية تلقائية:** الكود بمجلد `backup/` — يحتاج مستودع **خاص** بـ GitHub اسمه `sora3a-backup` (الشرح كامل بـ `backup/README.md`).
